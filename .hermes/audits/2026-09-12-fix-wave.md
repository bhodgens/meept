## Regression review of the fix commits (4 reviewers, deleg_9b35f02b, 2026-09-13)

Verdict: the fix wave introduced its own defects. 30 items found; 6 HIGH/MED
ones matter.

- HIGH: the FIXED hook `go_list_state` captured the load error with `2>&1`, so
  on a cold module cache the unrelated `go: downloading ...` stderr text was
  classified as `broken` and the hook BLOCKED healthy commits. This is the
  worst kind of regression: a gate that blocks legitimate work. (fix wave 2,
  group C)
- HIGH: the eval coverage floor withdrew the verdict for the policy it did not
  annotate, so the committed FAIL artifact and the report table now disagree.
- HIGH: an ALLOWED route veto released the exit-guard registration without
  navigating, so a browser Back plus "discard and exit" left the panel on
  screen with an empty registry - the next tool switch then dropped edits
  silently. The commit's own test proves it (it calls router.go('/') itself).
- MED: gitVerbRe over-narrowed ('merging', 'rebasing', 'uncommitted' no longer
  match), re-opening the misroute the word-boundary fix was written to close.
- MED: the recall-before-imperative reorder now swallows imperative WORK
  requests that carry a trailing status clause.
- MED: the ralph cap fix made the cap conditional on a heuristic the daemon
  envelope always satisfies (its synthetic "job <id> completed by agent" entry).
- MED: the schedule lane still creates a task that no path ever schedules
  (ShouldCreateTask true, ShouldDispatchAsync false).
- MED: a stale auto_stop=false spawn record permanently disables the boot sweep
  for an endpoint and then blocks the spawn.
- MED: the F76 bracket rewrite mines a JSON array element when prose before it
  contains an apostrophe, and drops a call on another prose shape.
- MED: a failed process-list scan is classified as "pid absent", so Stop reports

- MED: the autonomous turn marker does not survive park/resume, re-creating the
  staged-write-nobody-accepts defect for a throttled step job.
- MED: the new root-artifact hook assertion false-positives on any root file

- LOW/LOW-MED (14 more): stale ValidationError after a later passing validator;

## Wave-3 review of the wave-2 fixes (4 reviewers, deleg_c0d5b789, 2026-09-13)

The wave-2 review found 24 more items, 5 of them HIGH, and the pattern is the
same one level deeper: a fix that changes a RULE must be reviewed for the cases
the OLD rule handled, and a fix that adds a GATE must be reviewed for what it
now refuses.

- HIGH: the recall fix REVERSED the arbitration for genuine recall questions
  ("hey, did the change get made?" kept the untrusted git verdict) - the run-10
  failure the guard exists to close. The clause narrowing now applies only when
  an imperative leads, and . ? ! are separators.
- HIGH: leadingRecallClause PANICKED - it computed an index in
  strings.ToLower(input) and sliced input, so a multi-byte character before a
  separator gave "slice bounds out of range". The repo's byte-arithmetic audit
  whitelists ToLower, so CI could not see it. Now a case-insensitive regexp over
  the original input.
- HIGH: the ralph cap failed genuinely finished attempts. It required
  independent evidence, but a step job's only evidence entry is the daemon's
  synthetic stamp; real tool evidence arrives under a sibling JSON key the loop
  never read.
- HIGH: the miner's whole-content bracket veto re-armed the bug it fixed (one
  unbalanced bracket or a later apostrophe made a genuine array element
  mineable), and the truncation carve-out could mint a call from a prose
  example. Element-ness is now decided per object by pairing.
- MED: a privacy regression in the wave-2 payload - it wrote full verbatim ruler
  text into a tracked directory. Margin rows now carry the case key instead.
- MED: dispatchConsumesTask was applied to only one of two task-creation sites;
  the pair/collaborate arms were dead; and the laneForcesSequentialCompound
  value has no reader, so neither wave-1's "regression" nor wave-2's fix changed
  behaviour (comment corrected, no behaviour claim).
- MED: the build-artifact block list was a closed set missing three package-main
  names; the e2e remap detected spawn-bearing providers by substring (a comment
  re-introduced the bug) and its port patterns were narrower than the daemon's
  own accepted forms; the eval guard's parse bound "unparseable" to "empty" so a
  JSON5 ruler was refused permanently; a rewritten arithmetic line read 87.075%
  where it claimed 85.27%.
- MED: the CI gate added in 57d37000 claimed the eval self-test was pure stdlib;
  eval_harness imports numpy at module level, so the gate would have failed on a
  clean runner for the wrong reason. Fixed in e1c6e89d.
- MED: the promoted-reasoning text was discarded on the exhaustion path (the
  turn returned the generic error sentence); the GUI's new in-flight latch could
  latch forever; the window close path's "shares one answer" claim was false.
